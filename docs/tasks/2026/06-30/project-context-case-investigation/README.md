# Project-context 케이스 조사

이 문서는 케이스 문서 묶음의 읽는 순서만 맡는다.

## 읽는 순서

- `BRIEF.md`: 현재 재개 상태
- `cases/`: 케이스별 사실 조사 문서
- `SKILL-IMPROVEMENT-PROPOSAL.md`: 케이스 분류와 하위 에이전트 리뷰를 반영한 스킬 개선안
- `archive/code-related-cases/`: 코드 수정, 성능 조사, 배포가 본 사건이라 분석 대상에서 뺀 케이스
- `working/`: 하위 에이전트 원자료
- `logs/WORKLOG.md`: 작업 경과
- `logs/DECISIONS.md`: 조사 방식 결정

## 케이스 문서 원칙

- 한 파일은 한 사건만 다룬다.
- `cases/`에는 `project-context`가 다루는 문서 작업 사건만 둔다.
- 코드 수정, 성능 조사, 배포가 본 사건인 파일은 `cases/`에 두지 않는다.
- 첫머리에 사용자 지적/요청, 에이전트 조치, 드러난 문제를 쓴다.
- 확인한 사실과 증거는 그 뒤에 둔다.
- 해석, 개선안, 권장안은 쓰지 않는다.
- 모르는 것은 모른다고 쓴다.
- 파일명, 명령, 코드 식별자, 제품명은 그대로 둔다.

## 개선안 문서 원칙

- 케이스 문서에는 사실만 두고, 반복 문제와 제안은 `SKILL-IMPROVEMENT-PROPOSAL.md`에서 다룬다.
- 제안은 배포 대상 `project-context` 스킬에 넣을 최소 규칙만 다룬다.
- 하위 에이전트 리뷰에서 기각된 범위 확장은 문서에 보류 사유를 남긴다.
