# playground 조사 요약

## 가져온 문제

- `BRIEF.md`가 현재 상태 문서가 아니라 작업 보고서처럼 길어진다.
- 사용자 정정이 현재 상태 변경으로 반영되지 않고 “왜 바꿨는지” 설명으로 보존된다.
- 삭제할 내용을 실제로 없애기보다 “빼야 한다”는 문장으로 다시 남긴다.
- 같은 결론이 `BRIEF.md`, 제안 문서, 근거 문서에 반복된다.

## project-context에 해당하는 부분

- 현재 상태 문서와 로그의 경계
- `BRIEF.md`의 rewrite-only 성격
- 재개에 필요한 현재 사실과 작업 기록의 분리

## project-context가 맡지 않을 부분

- 문서 패키지의 의미 품질 전반: `structure-first-docs`
- 현재 코드/API/문서 소유자 감사: `source-owner-audit`
- 항상 읽히는 리포 지침: 각 리포 `AGENTS.md`

## 검토 기준

새 문구가 필요하다면 `BRIEF.md`와 logs 경계를 더 선명하게 해야 한다. 새 문구가 단지 “하지 말라” 목록을 늘린다면 보류하는 편이 낫다.
